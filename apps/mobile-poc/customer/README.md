# SRK ELECTRONIC — Customer Capacitor POC

**Scope:** isolated, internal proof-of-concept only. This is not the Customer production app, not the Electrician app, and not a Play Store release.

## What this POC tests
- Owner-supplied founder photo in a crisp, centered waist-up mobile crop.
- Compact blue/white/gold welcome composition with less unused top space.
- Capacitor 8 Android WebView packaging and screen rendering.
- Restore and validate an existing Supabase Auth session.
- Read-only list of the signed-in customer's own booking summaries using the existing public/publishable Supabase key and RLS.

## Safety boundaries
- No OTP is sent automatically; no SMS/OTP provider is activated by this POC.
- No booking creation, accept/decline, timer, materials, payment, wallet mutation, or profile update.
- No sample customer, location, price, rating, booking or wallet data is fabricated.
- Booking query is restricted by authenticated `customer_user_id`; it requests only ID, service type, status, preferred date and created date. RLS remains authoritative.
- No service-role key, Razorpay secret, signing key, or other privileged secret is included.
- Temporary package ID: `in.srkelectronic.poc.customer`. It is not the proposed final Customer application ID.
- No Production deployment, database migration, paid provider activation or app publication.

## Build locally
Requirements: Node.js 22+, Android Studio 2025.2.1+, Android SDK API 24+ and Java supplied by Android Studio, per Capacitor 8 requirements.

```sh
cd apps/mobile-poc/customer
npm install
npm run build
npx cap add android
npx cap sync android
cd android
./gradlew assembleDebug
``

The Android directory is generated by Capacitor during the build and is not committed by the POC setup. The CI workflow generates it in a clean runner and uploads a debug APK for internal inspection.

## Known POC limitation
A fresh Android WebView has no existing login session. Since this POC deliberately does not send OTP, it will show the signed-out state until a safe test session is established through an explicitly approved test method. Do not paste tokens or credentials into the app or repository. This POC verifies session restoration when a valid session is present; it does not claim that OTP login has been completed.

## Acceptance gates
1. Asset preparation copies only the approved founder photo and browser-safe config.
2. Static HTML/script checks pass.
3. Capacitor configuration validates and Android project generation succeeds.
4. Debug APK builds successfully in CI.
5. Physical-device visual review confirms face clarity, waist-up crop, compact top section and no clipped content.
6. Session restore and RLS-scoped read-only booking query pass with an authorized test session.
7. No production API mutation, OTP, payment, or privileged secret usage.
